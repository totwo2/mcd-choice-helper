# 麦门选择困难症助手（mcd-choice-helper）

> 2026 麦当劳程序员创意开发大赛参赛作品 · 基于麦当劳中国官方 MCP 构建
> 由参赛者独立开发，非麦当劳官方产品。

## 它解决什么问题

很多人站在麦当劳门口/打开 App 就犯"选择困难"：菜单太长、券太多、不知道怎么凑最划算。
本助手**直接给结论**——打开就推当下最划算的组合；你说"预算 30 怎么点"，它帮你拼。

- ✅ 能读你的**历史订单** → 做口味偏好/趋势判断，推你爱吃的
- ✅ 按**门店真实时段窗**判断该吃啥（早餐 05:14–10:15、午餐、下午茶、夜市、宵夜，按店按日变，非写死时间表）；**过点的商品绝不推荐**（实测：午餐时段真实菜单里仍混有早餐商品，本助手按时段窗+商品标记将其剔除）
- ✅ 你说预算 → 在预算内自动拼单、套最优券
- ❌ **硬约束**：绝不为凑价推荐"全都是饮料"的套餐（至少含 1 份正餐/主食）

## 安装

1. 申请麦当劳 MCP Token：`https://open.mcd.cn/mcp`（手机号登录 → 控制台 → 激活）
2. 配置到 WorkBuddy 连接器（或本地 `mcp_client.py` 读 `MCD_TOKEN` 环境变量）
3. 本地验证（无需 Token）：
   ```bash
   python demo.py            # 内嵌样例演示
   python demo.py --budget 30
   ```
4. 接真实数据（自动搜店 → 解析门店真实时段窗 → 拉真实菜单与优惠券）：
   ```bash
   export MCD_TOKEN="你的Token"
   python demo.py --keyword 春熙路       # 按关键词搜店
   python demo.py --store 3450410        # 指定门店编码
   python demo.py --keyword 春熙路 --budget 30
   ```

## 预算拼单算法（combo_optimizer.py）

1. **候选池收窄**：先按时段可用性过滤（早餐类商品过供应时段直接出局），再分三堆——官方套餐 / 正餐类单品 / 饮料。
2. **主食打底**：正餐单品按时段与历史口味加权，取前 5 名各生成一条候选线；主食单独就超预算的候选线直接放弃。
3. **逐步凑单（局部最优）**：加小食、加饮料两步，都是在「加进去后实付仍 ≤ 预算」的候选里**枚举并选实付最低（省最多）的一个**，不是取第一个塞得下的。
4. **券取最优**：每一步对整个组合在所有可用券中取优惠最大的一张（满减 / 折扣 / 单品立减三类）。
5. **硬约束兜底**：每条候选输出前校验——实付 ≤ 预算、组合至少含 1 份正餐（禁"全饮料凑价"）。
6. **排序**：官方套餐与拼单组合同池竞争，省得多者优先，省一样多时实付越贴近预算越靠前，取 Top 3。

已知取舍：券不叠加（单张最优）；"1 主食 + 1 小食 + 1 饮料"结构不做指数级全局枚举，以可复现与稳定为先。

## 目标用户

- 选择困难、懒得研究菜单与优惠的人
- 想"花最少钱吃到想吃的"的精打细算党
- 麦当劳高频顾客（历史订单越多，推荐越准）

## 设计取舍

- **默认只读+算价，不自动下单**：`create-order` 需用户显式确认，守住钱包安全。
- **套餐与自由拼并行**：官方套餐本身合理，直接作为候选；自由拼用于预算/偏好场景。
- **可复现优于纯语言推理**：组合枚举交给 `combo_optimizer.py`，结果稳定、可单测。
